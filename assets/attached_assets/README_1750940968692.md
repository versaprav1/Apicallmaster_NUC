# WHINT API Data Q&A with LLM

This Streamlit app allows you to fetch, store, explore, and query integration interface data from the WHINT Integration Cockpit API. It leverages a local JSON database for efficient, large-scale data handling and uses an LLM (such as OpenAI GPT-4) to answer natural language questions about your integration landscape.

---

## Features

- **Paginated API Fetch:** Fetches all available data from the WHINT API using pagination, merging new data with existing local data and avoiding duplicates.
- **Local Data Storage:** Stores all data in `all_data.json` for fast, repeated access and offline querying.
- **Daily Auto-Refresh:** Automatically refreshes the local data once per day, or on demand via a button.
- **Download Options:** Download the full dataset as JSON or CSV.
- **Data Summary:** Scrollable summary of interfaces, showing name, description, sender, receiver, and sample property/tag.
- **Natural Language Q&A:** Ask questions about your data in plain English. The app uses Python for heavy data processing and the LLM for language understanding and explanation.
- **Direct Property/Tag Lookup:** For questions like "What is the URL property for interface X?", the app answers directly from the data without using the LLM.

---

## How It Works

1. **Fetching Data:**
   - Click **Fetch All Data from API (Full Download)** to retrieve all records from the API (using pagination) and store them in `all_data.json`.
   - The app also auto-refreshes the data once per day.

2. **Exploring Data:**
   - The app displays a scrollable summary of your interfaces.
   - You can download the full dataset as JSON or CSV.

3. **Asking Questions:**
   - Enter a natural language question (e.g., "What is the country tag for interface X?").
   - The app uses Python to extract direct answers when possible, or summarizes relevant data and sends it to the LLM for more complex queries.

4. **Efficient LLM Use:**
   - Only relevant, summarized data is sent to the LLM, ensuring fast and cost-effective answers even for large datasets.

---

## What Questions Can Be Answered?

- List all interfaces and their details (name, description, sender, receiver).
- Show all properties or tags for a given interface.
- Find the value of a specific property or tag for an interface.
- List interfaces with a specific sender, receiver, property, or tag value.
- Show items/inventory details for an interface.

**Not Supported:**
- Time-based or usage-based queries (no date/timestamp fields in the data).
- Data not present in the API response (e.g., logs, run history).

## Setup & Usage

1. **Install Requirements:**
   ```sh
   pip install streamlit requests openai pandas
   ```

2. **Configure Secrets:**
   - Add your API keys and tokens to `.streamlit/secrets.toml`:
     ```toml
     openai_api_key = "YOUR_OPENAI_API_KEY"
     whint_api_base_url = "https://whint.prod.apimanagement.eu10.hana.ondemand.com:443/api"
     whint_api_bearer_token = "YOUR_BEARER_TOKEN"
     whint_api_x_api_key = "YOUR_X_API_KEY"
     ```

3. **Run the App:**
   ```sh
   streamlit run app.py
   ```

4. **Fetch Data:**
   - Click **Fetch All Data from API (Full Download)** to populate your local database.
   - Use the **Download Data** expander to export your data.

5. **Ask Questions:**
   - Use the input box to ask questions about your data.

## File Structure

- `app.py` — Main Streamlit app.
- `all_data.json` — Local database of all fetched interface data.
- `last_fetch.txt` — Timestamp of last full data fetch.
- `response.json` — (Optional) Example API response.
- `.streamlit/secrets.toml` — API keys and configuration (not included in repo).

---

## Customization

- **Data Model:**
  - The app expects each interface to have fields like `name`, `description`, `sender`, `receiver`, `properties`, `tags`, and `items`.
- **LLM Model:**
  - Uses OpenAI GPT-4 by default, but can be adapted for other LLMs.
- **Data Processing:**
  - You can extend the Python logic to support more advanced filtering, aggregation, or custom queries.

---

## Limitations & Notes

- The app does not support time-based queries unless your API/data includes date fields.
- For very large datasets, all processing is done in Python before sending a summary to the LLM to avoid token/context window issues.
- The app is designed for interactive, session-based use and does not persist user queries or answers.
